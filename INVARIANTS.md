# INVARIANTS.md
Правила, которые нельзя нарушать.

## I1. Источник истины
Для каждого вида состояния существует один явный источник истины.
- Статус проекта → CURRENT_STATE.md
- Решения → DECISIONS.md (accepted)
- Происхождение утверждений → PROVENANCE.md
- Архитектура → docs/ARCHITECTURE.md (если существует)
- Метод → docs/METHOD.md (если существует)

Документация определяет систему. Документация сама по себе не является доказательством фактического исполнения.

## I2. Состояния знания
Эпистемический статус и тип утверждения — независимые измерения (см. docs/KNOWLEDGE_STATES.md).
Тип утверждения (OBSERVATION / RESULT / INTERPRETATION) не является эпистемическим статусом и не переходит в него автоматически.

Запрещено автоматическое повышение эпистемического статуса без явного основания:
- UNKNOWN → любое другое значение
- HYPOTHESIS → SUPPORTED / VERIFIED
- SUPPORTED → VERIFIED

Любой переход статуса фиксируется в meta/transitions.md со ссылкой на основание.

## I3. Append-only для первичных данных
Первичные записи (records/, trace, полевые логи, исходные материалы) не перезаписываются.
Исправления только через новую запись с указанием причины.

## I4. Provenance
Значимые утверждения со статусом SUPPORTED или VERIFIED, а также утверждения типа RESULT, должны иметь прослеживаемое происхождение в PROVENANCE.md или эквивалентной записи.

## I5. Изменение инвариантов
Изменение любого правила этого файла допускается только через запись в DECISIONS.md со статусом accepted.

**Исключение (инициализация):** при первом создании проекта допускается запись D-000000-00 с пометкой «initial setup» без требования предыдущего accepted decision.

## I6. Удаление
Документы и записи не удаляются. Устаревшее перемещается в ARCHIVE/ с указанием даты и причины.

## I7. Проверяемость состояния
Нормативные документы определяют требуемое поведение, но не считаются доказательством фактического исполнения.
Значимые утверждения о состоянии системы должны иметь проверяемое основание.
Дата обновления документа не заменяет дату и результат проверки.

## I8. Синхронизация
После фиксации решения в DECISIONS.md со статусом accepted в течение 24 часов должен быть обновлён CURRENT_STATE.md. Если обновление невозможно, причина фиксируется в разделе «Заблокировано» CURRENT_STATE.md с указанием даты и условия разблокировки.

## I9. Иерархия источников истины
Любое утверждение о внешнем артефакте требует источника. Приоритет — от высшего к низшему:
1. Текущий ввод оператора.
2. Свежий терминальный вывод в текущей сессии (git status, git log, содержимое файлов).
3. Содержимое репозитория по конкретному SHA.
4. Документация проекта (INVARIANTS, CURRENT_STATE, DECISIONS, meta).
5. Handoff / сводки предыдущих чатов.
6. Память агента / реконструкция.

Уровень 6 не используется для утверждений о фактах. При конфликте берётся более высокий уровень.

## I10. Свежесть
«Свежий» — полученный в текущей сессии, а не вспомненный или скопированный из предыдущего handoff.
Утверждение из предыдущего handoff не устанавливает текущее состояние. При конфликте между памятью агента и свежим проверяемым выводом побеждает свежий вывод.

## I11. Восстановление утраченного сырья
Реконструкция утраченного сырья по памяти или по резюме недопустима.
Допустимо только: повторный запрос у источника с сохранением как `archived-external`, либо явная фиксация `UNKNOWN`.
