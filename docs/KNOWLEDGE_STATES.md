# docs/KNOWLEDGE_STATES.md
Модель состояний знания (двумерная).
Одно утверждение может иметь и эпистемический статус, и тип.

## 1. Эпистемический статус

Что известно и насколько обосновано.

- **UNKNOWN** — явно обозначенный пробел. Не заполняется предположениями.
- **HYPOTHESIS** — проверяемое объяснение. Требует процедуры проверки.
- **SUPPORTED** — имеет подтверждающие данные, но ещё не прошло полную верификацию.
- **VERIFIED** — подтверждено установленной процедурой или источником.

## 2. Тип утверждения

Что представляет собой утверждение.

- **OBSERVATION** — непосредственно зафиксированное наблюдение.
- **RESULT** — результат выполненной процедуры (эксперимент, измерение, действие).
- **INTERPRETATION** — объяснение значения наблюдения или результата.

## 3. Правила

- Одно утверждение может иметь и эпистемический статус, и тип.
- Переход эпистемического статуса фиксируется (`meta/transitions.md` или через `PROVENANCE.md` + `DECISIONS.md`).
- `INTERPRETATION` никогда не становится `VERIFIED` автоматически только потому, что красиво сформулирована.
- `RESULT` не является автоматически `VERIFIED`.

## 4. Компактные маркировки (operational shortcut)

Для быстрой разметки утверждений прямо в тексте используются компактные маркировки.
Это не замена двумерной модели, а её краткая форма для рабочего обмена.

| Маркировка | Значение | Соответствие в модели |
|---|---|---|
| `[ФАКТ]` | Подтверждено источником, источник назван | SUPPORTED/VERIFIED × (OBSERVATION/RESULT) |
| `[ГИПОТЕЗА]` | Предположение, источник не подтверждает | HYPOTHESIS × (любой тип) |
| `[НЕИЗВЕСТНО]` | Данных нет | UNKNOWN |
| `[МОЯ ПОЗИЦИЯ]` | Операционная или аналитическая позиция агента по текущему вопросу, не факт | не входит в модель — рабочее суждение |
| `[ВНЕШНИЙ — <имя>]` | Дословный вывод внешнего наблюдателя, присланный в текущем чате | внешний источник, требует атрибуции |

Правила использования маркировок — см. `meta/handoff-protocol.md` §5.

## 5. Что не допускается

- Автоматическое повышение статуса (см. I2).
- Заполнение `UNKNOWN` предположением без основания.
- Использование `[МОЯ ПОЗИЦИЯ]` для маскировки внешнего мнения.
- Восстановление дословного текста внешнего наблюдателя по памяти.

## 6. Связь с PROVENANCE.md

Утверждения уровня SUPPORTED / VERIFIED и типа RESULT должны иметь запись в `PROVENANCE.md` (I4). Запись фиксирует: утверждение, эпистемический статус, тип, источник, процедуру, результат проверки, ограничения.

Переходы статуса фиксируются в `meta/transitions.md` (I2).
