# docs/METHOD.md
Метод сбора снимков состояния хоста `nova`.

## 1. Область применения

Сбор структурированных снимков состояния хоста `nova` по запросу оператора. Один снимок = один файл в `records/` с timestamp.

## 2. Базовый принцип

Сначала наблюдение, потом запись. Не модифицировать состояние хоста. Не интерпретировать данные при сборе: фиксировать raw-вывод команд и мета-данные как есть.

## 3. Полевой цикл (адаптированный для утилиты)

 REQUEST
 ↓
 COLLECT (df, free, uptime, docker ps, git scan)
 ↓
 RECORD (структурированный файл в records/)
 ↓
 VERIFY (проверить, что файл записан и читаем)
 ↓
 GIT (commit + push, если зеркало доступно)
 ↓
 NEXT

## 4. Два контура

Для утилиты-инструмента контуры упрощены:

### Сборочный контур
 Запрос → сбор → запись → проверка файла

### Интерпретационный контур (вне MVP)
 Сравнение снимков → выводы о динамике — за границей MVP, см. VISION.md

## 5. Состояния знания

Базовая модель — см. `docs/KNOWLEDGE_STATES.md`.

Для снимков:
- `FACT` — подтверждено терминальным выводом в текущей сессии.
- `OBSERVATION` — зафиксировано в `records/`, но не поднято до более высокого уровня.
- `HYPOTHESIS` — предположение о причине изменения (вне MVP).
- `UNKNOWN` — данные не собраны или команда не сработала.

## 6. Минимальная полевая запись

Формат снимка (будет уточнён в ARCHITECTURE.md):

- TIMESTAMP
- HOST
- DISK
- MEMORY
- UPTIME
- DOCKER
- GIT_REPOS
- UNKNOWN (что не удалось собрать)
- NEXT STEP

## 7. Run Structure

Каждый завершённый прогон обязательно производит:

1. Запись прогона (run record) в `records/`.
2. Сохранённые сырые выходы команд (или явный маркер `UNKNOWN`).
3. Git commit.
4. Git push в origin/main (если зеркало доступно).
5. Проверка: локальный HEAD, удалённый HEAD, чистое рабочее дерево.

## 8. Провенанс (слои)

- `raw-external` — терминальный вывод команд в момент сбора.
- `RUN RECORD` — структурированный снимок в `records/`.
- `DECISION` — если в ходе прогона принято решение.
- `NEXT OBSERVATION` — что проверить в следующем прогоне.

## 9. Git Rule

После каждого завершённого прогона:

1. Сохранить сырые выходы и снимок.
2. Commit.
3. Push в `origin/main` (если зеркало доступно).
4. Проверить: `git log -1 --oneline`, `git status --short`.

## 10. Ограничения

- Без sudo: некоторые команды (например, `docker ps` без прав группы docker) могут не сработать. Несработавшая команда фиксируется как `UNKNOWN` в снимке, не пропускается молча.
- Только чтение: никакие команды не изменяют состояние хоста.
- Работа через оператора: агент не имеет прямого доступа к терминалу, команды передаются через оператора.
