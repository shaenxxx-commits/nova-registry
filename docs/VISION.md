# docs/VISION.md
Границы и назначение проекта nova-registry.

## Что это

nova-registry — локальная утилита для хоста `nova`, которая по запросу собирает снимок текущего состояния системы и сохраняет его в `records/` с timestamp.

Что входит в снимок:
- свободное место на дисках (`df`);
- использование памяти (`free`);
- uptime хоста;
- список запущенных docker-контейнеров (`docker ps`);
- список git-репозиториев в домашнем каталоге оператора (`~`): путь, текущая ветка, статус рабочего дерева, приблизительный объём.

## Что это не

- Не система мониторинга в реальном времени (нет демона, нет алертов).
- Не инструмент изменения состояния (только чтение и сбор данных, никаких модификаций хоста).
- Не резервное копирование (не копирует файлы, только мета-информацию о состоянии).
- Не аудит безопасности (не проверяет права, уязвимости, конфигурации).
- Не публичный сервис (работает локально на хосте `nova`, GitHub-зеркало — только для документации и кода).

## Границы проекта

В рамках MVP:
- работа без sudo, только прямой запуск от пользователя `shaen`;
- выходной формат — структурированный файл (JSON, YAML или Markdown) в `records/`;
- один снимок — один файл с timestamp;
- git-репозитории сканируются рекурсивно в `~`, но без входа внутрь содержимого (только мета-данные git).

За границей MVP:
- исторические сравнения между снимками;
- визуализация или дашборды;
- интеграция с внешними системами;
- автоматический запуск по расписанию.

## Почему VISION заполнен, а не оставлен заготовкой

Для утилиты-инструмента без исследовательской повестки VISION.md служит операционным ограничителем: он фиксирует, что проект делает и чего не делает, чтобы предотвратить «ползучее расширение» в сторону мониторинга, бэкапа или аудита. Это соответствует принципу каркаса: границы определяются явно, а не выводятся из контекста.
